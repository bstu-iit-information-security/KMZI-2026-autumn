**RSA-3072 · OAEP (MGF1-SHA-512) · задача оптимизации: constant-time алгоритм Гарнера в CRT (без `if (m1 < m2)`)**

Язык: C++17. GMP — только арифметика больших чисел (`+ − × mod`, `powm_sec`). SHA-512, MGF1, OAEP, расширенный алгоритм Евклида, тест Миллера–Рабина, генерация простых и ключей, CRT/Гарнер написаны вручную.

## 1. Математическая часть

### Ускорение расшифрования через CRT
Стоимость модульного возведения в степень при модуле в *n* бит: экспонента имеет ≈ *n* бит (≈ *n* квадратов и ≈ *n*/2 умножений), каждое умножение стоит M(n) ≈ c·n² (школьное умножение). Итого T(n) ≈ c′·n³.

- Прямое расшифрование: T(n) = c′·n³.
- CRT: две экспоненты по модулям ≈ n/2 бит, показатели d_p, d_q тоже ≈ n/2 бит:
  2·T(n/2) = 2·c′·(n/2)³ = c′·n³/4.

Теоретическое ускорение ×4 (с учётом Карацубы и накладных расходов на редукции и Гарнер оно чуть меньше или близко к 4).
**Измерено** (`./bench_crt`, RSA-3072): прямое 18.4·10⁶ тактов, CRT 4.52·10⁶ тактов, **ускорение 4.07×**.

### Корректность алгоритма Гарнера
m ≡ m₁ (mod p), m ≡ m₂ (mod q). Ищем m = m₂ + h·q. Из m ≡ m₁ (mod p): h ≡ q⁻¹·(m₁ − m₂) (mod p), т.е. h = q_inv·(m₁ − m₂) mod p. Так как h < p, то m = m₂ + h·q < q + (p−1)q = pq = N.

### Пример на малых числах (p=61, q=53, e=17, d=2753, N=3233, m=65)
- c = 65¹⁷ mod 3233 = 2790
- d_p = 2753 mod 60 = 53, d_q = 2753 mod 52 = 49, q_inv = 53⁻¹ mod 61 = 38
- m₁ = 2790⁵³ mod 61 = 4, m₂ = 2790⁴⁹ mod 53 = 12
- m₁ − m₂ = −8 < 0 → добавляем p: −8 + 61 = 53
- h = 38·53 mod 61 = 2014 mod 61 = 1 → **m = 12 + 1·53 = 65** ✓

В «лобовой» реализации здесь сработало бы `if (m1 < m2)` — именно оно и есть утечка. Программа также перебирает все m ∈ [0, N) для обоих порядков (p>q и p<q): ветвь m₁<m₂ срабатывает в 1378 и 1802 случаях из 3233, результат всегда верен.

### Constant-time шаг Гарнера (идея)
Нужно вычислить (m₁ − m₂) mod p без `if`.
1. m₂ < 2p (т.к. у p и q по 1536 бит с двумя единичными старшими битами, 1.5·2¹⁵³⁵ ≤ p,q < 2¹⁵³⁶), значит `m₂ mod p` — одно условное вычитание: `t = m₂ − p`, заём `b` (1, если m₂ < p), маска `keep = 0 − b`, `m₂' = (m₂ & keep) | (t & ~keep)`. Для запаса выполняется дважды.
2. `t = m₁ − m₂'` (`mpn_sub_n`, 24 лимба), заём `b'`, маска `mask = 0 − b'`.
3. Безусловно `t += p & mask` (`mpn_add_n`). Результат в [0, p).
Операции над лимбами выполняются всегда, в одинаковом количестве, независимо от соотношения m₁ и m₂.

## 2. Архитектура (поток данных)
```
 M (0..254 байта) , Label ("")
        │
        ▼  [Модуль 3: OAEP.encode]
 lHash = SHA-512(Label)          seed ← getrandom (64 байта)
 DB = lHash ‖ PS(0x00…) ‖ 0x01 ‖ M          (319 байт, статический массив)
 maskedDB   = DB ⊕ MGF1(seed, 319)
 maskedSeed = seed ⊕ MGF1(maskedDB, 64)
 EM = 0x00 ‖ maskedSeed ‖ maskedDB          (384 байта = k)
        │
        ▼  [Модуль 2: encrypt_raw]   c = EM^e mod N   → 384 байта шифротекста
 ─────────────────────────────── канал ───────────────────────────────
        ▼  [Модуль 2: decrypt_crt]
 c_p = c mod p, c_q = c mod q
 m₁ = c_p^d_p mod p, m₂ = c_q^d_q mod q        (mpz_powm_sec)
 diff = (m₁ − m₂) mod p     ← constant-time (mpn_sub_n / маска / mpn_add_n)
 m = m₂ + q·(q_inv·diff mod p)
        │
        ▼  EM = int_to_bytes(m, 384)   (фиксированное число лимбов)
        ▼  [Модуль 3: OAEP.decode, constant-time]  → M, len(M) или единый признак ошибки
```
Модуль 1 даёт `PublicKey/PrivateKey` и примитивы; модуль 2 ничего не знает про OAEP; модуль 3 знает про RSA только через `encrypt_raw`/`decrypt_crt`.

## 3. Анализ безопасности (constant-time)

**Память.** Все буферы OAEP — массивы фиксированного размера на стеке: `uint8_t em[384]`, `db[319]`, `mask[319]`, `seed[64]`, `uint64_t a[24]`. `std::vector` и вложенные контейнеры в модулях 1–3 не используются (`std::vector` есть только в измерительном коде `tests.cpp`, он не входит в криптоядро). Секреты затираются `ct::secure_zero` (volatile-запись, не вырезается оптимизатором); деструктор `BigInt` затирает лимбы перед `mpz_clear`. Размеры больших чисел при конвертации фиксированы (`P_LIMBS=24`, `N_LIMBS=48`), несоответствие размера приводит к `abort`.

**Отсутствие ветвлений, зависящих от секрета, в `garner_diff_ct`.**
Функция состоит из: (а) копирования в массивы фиксированной длины (циклы с константными границами 24); (б) `mpn_sub_n` / `mpn_add_n` — ассемблерные примитивы GMP без ветвлений по данным; (в) выражений `(a & mask) | (b & ~mask)`, где `mask = 0 − borrow` — чистая арифметика; (г) циклов `for (i<24)` с публичным счётчиком. Единственный `if` — проверка размера в `to_limbs` (предусловие, не зависит от значения). Любой путь исполнения выполняет один и тот же набор инструкций, откуда следует, что число тактов и последовательность адресов памяти не зависят от результата сравнения m₁ и m₂. В ассемблере (`g++ -O2 -S`) в функции остались только условные переходы счётчиков циклов и проверки размера.

**OAEP.decode** (профилактика атаки Блейхенбахера/Мангера): все проверки выполняются до конца. Аккумулятор `err` собирает `em[0]` и XOR всех 64 байт lHash; поиск `0x01` — безусловный проход по всему DB с масками `eq_mask`; мусор в PS попадает в маску `bad`; извлечение сообщения — сдвиг DB на `idx+1` байт девятью ступенями (по биту сдвига) без индексации по секретному смещению. Выход всегда `MAX_MSG` байт, при ошибке все нули и длина 0. Наружу уходит единственный бит «успех/ошибка».

**Результаты замеров** (rdtsc, чередование замеров, медианы; `test_output.txt`):

| OAEP.decode, CT: неверный lHash | 18 586 | 18 580 | −0.03 % |

**Честные ограничения.**
- В тесте разрешена GMP только для арифметики, поэтому `mpz_mul`, `mpz_mod` (вторая половина Гарнера: `q_inv·diff mod p`, `m₂ + h·q`) и `mpz_export` выполняются библиотекой и не гарантируют постоянного времени на уровне микроархитектуры. Наш код не содержит ветвлений по секретам, но полностью constant-time шаг умножения/редукции потребовал бы собственной арифметики Монтгомери на фиксированных лимбах. Возведение в степень использует `mpz_powm_sec` (side-channel silent).
- `mpz_t` внутри GMP выделяет память в куче (внутренние лимбы), поэтому «heap-free» в строгом смысле относится к буферам OAEP/ключевых байтов (вариант 10 в нашем задании не требуется).
- Тест Миллера–Рабина и генерация простых не constant-time (это вариант 11); утекают только отвергнутые кандидаты.
- Замеры — rdtsc на x86-64; на другой архитектуре или при другом компиляторе их нужно повторить, а ассемблер перепроверить (компилятор теоретически вправе превратить маски в переходы).

## 4. Результаты тестирования (`make check`, 0 провалов)
- SHA-512: три известных вектора (пустая строка, `abc`, 112-байтное сообщение на два блока).
- Теория чисел: ext_gcd(240,46)=2; 17⁻¹ mod 3120 = 2753; Миллер–Рабин отвергает 561 (число Кармайкла), принимает 104729 и 2¹²⁷−1.
- Гарнер на малых числах: полный перебор всех m ∈ [0, 3233) для обоих порядков p и q.
- Ключи RSA-3072: N ровно 3072 бит, p, q по 1536 бит, p≠q, e·d_p ≡ 1 (mod p−1), e·d_q ≡ 1 (mod q−1), q·q_inv ≡ 1 (mod p).
- CRT == прямое c^d mod N на 20 случайных m; `garner_diff_ct == garner_diff_naive` на 20 000 случайных 1536-битных пар (в 15 124 из них m₁<m₂).
- **Граничные условия OAEP:** длина сообщения 0, 1, 100 и **254 = k−2hLen−2** — успешно; длина 255 отвергается; метка совпала/не совпала; два шифрования одного текста дают разные шифротексты; c ≥ N отвергается.
- Дефекты структуры EM: первый байт ≠ 0, неверный lHash, ненулевой байт в PS, отсутствие 0x01 — во всех случаях отказ, выходной буфер обнулён.
- Совместимость: шифротекст нашей реализации расшифрован OpenSSL (`rsa_padding_mode:oaep`, SHA-512, MGF1-SHA-512).

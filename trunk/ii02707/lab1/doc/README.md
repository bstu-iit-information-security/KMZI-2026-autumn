## 2. Математическая часть

### 2.1. Элементы поля GF(2⁸)

Элементы GF(2⁸) — многочлены степени не выше 7 над GF(2):

$$A(x) = a_7 x^7 + a_6 x^6 + a_5 x^5 + a_4 x^4 + a_3 x^3 + a_2 x^2 + a_1 x + a_0, \quad a_i \in \{0, 1\}$$

Каждому элементу соответствует байт `(a₇a₆a₅a₄a₃a₂a₁a₀)₂`.

**Для варианта 4 используется неприводимый многочлен:**

$$p(x) = x^8 + x^5 + x^3 + x + 1 = \text{0x12B}$$

### 2.2. Сложение

$$C(x) = A(x) + B(x) = \sum_{i=0}^{7} (a_i \oplus b_i) x^i$$

Реализация — побитовый XOR:

```cpp
static uint8_t add(uint8_t a, uint8_t b) { return a ^ b; }
```

**Вывод:** сложение в GF(2⁸) — это XOR, потому что характеристика поля равна 2 (`1 + 1 = 0`).

### 2.3. Умножение (shift-and-XOR)

**Шаг 1.** Обычное умножение полиномов даёт результат степени до 14:

$$P(x) = A(x) \cdot B(x) = \sum_{i=0}^{14} c_i x^i$$

**Шаг 2.** Редукция по модулю p(x):

$$C(x) = P(x) \bmod p(x)$$

**Алгоритм (8 итераций):**

```
result ← 0
for i = 0 to 7:
    если младший бит b = 1: result ← result ⊕ a
    a ← xtime(a)           // умножение a на x
    b ← b >> 1
return result
```

где `xtime` — умножение на x (0x02) с редукцией:

$$\text{xtime}(b) = \begin{cases} b \ll 1, & b_7 = 0 \\ (b \ll 1) \oplus \text{0x2B}, & b_7 = 1 \end{cases}$$

**Важно:** младшие 8 бит p(x) = 0x12B равны **0x2B** (старший член x⁸ сокращается самой операцией редукции).

### 2.4. Мультипликативно обратный элемент

Используется малая теорема Ферма для полей характеристики 2:

$$A^{-1} = A^{2^8 - 2} = A^{254} \pmod{p(x)}$$

**Цепочка квадратов (7 квадратов + 6 умножений):**

$$a^2, \; a^4 = (a^2)^2, \; a^8 = (a^4)^2, \; a^{16}, \; a^{32}, \; a^{64}, \; a^{128}$$

$$a^{254} = a^{128} \cdot a^{64} \cdot a^{32} \cdot a^{16} \cdot a^8 \cdot a^4 \cdot a^2$$

**Частный случай:** `inverse(0x00) = 0x00` — по определению, без деления на ноль.

**Почему именно 254:** `2⁸ - 2 = 254`, потому что мультипликативная группа GF(2⁸)\{0} имеет порядок 255, и `A²⁵⁵ = 1`, откуда `A⁻¹ = A²⁵⁴`.

### 2.5. Построение S-блока

S-блок строится как композиция:

$$S(b) = M \cdot b^{-1} + c$$

где `M` — циркулянтная 8×8 матрица над GF(2), `c = 0xA6` (константа для Belt).

Эквивалентная быстрая форма:

$$S(b) = b^{-1} \oplus \text{ROTL}(b^{-1}, 1) \oplus \text{ROTL}(b^{-1}, 2) \oplus \text{ROTL}(b^{-1}, 3) \oplus \text{0xA6}$$

**Свойства S-блока:** биекция, нелинейность, отсутствие неподвижных точек.

### 2.6. Построение H-блока Belt

H-блок БелТ (аналог S-box) строится по тому же принципу, что и S-box AES, но с полиномом `p(x) = 0x12B` и аффинной константой `0xA6`.

### 2.7. Операции в GF(2¹²⁸) для GHASH

Полином: `f(x) = x¹²⁸ + x⁷ + x² + x + 1`

Редукционная константа: `R = 0xE1` (младший байт в старшей позиции).

Умножение `X · Y` реализуется за 128 итераций:

```
Z ← 0
V ← Y
for i = 0 to 127:
    bit ← (X >> (127 - i)) & 1
    Z ← Z ⊕ (V & (-bit))
    lsb ← V & 1
    V ← V >> 1
    V ← V ⊕ (R & (-lsb))
return Z
```

Все операции — без ветвлений, маскирование через `-bit`.

### 3.3. Раундовые преобразования Belt

Один раунд прямого преобразования:

```
b ← b ⊕ G_r(a, K_r)
a ← a + b + 1  (mod 2³²)
(a, b, c, d) ← (b, c, d, a)  — циклический сдвиг регистров
```

Раундовая функция G_r:

```
x ← a ⊕ K_r
x ← H(x)          — побайтовая H-подстановка
x ← ROTL(x, r+1)  — Constant-time ROTL
return x
```

**Все 8 раундов** используют подключи `K_{r mod 8}`.

## 4. Анализ безопасности (Constant-time)

### 4.1. Задача варианта 4: безопасная круговая перестановка (ROTL/ROTR)

**Проблема классической реализации:**

```cpp
uint32_t rotl(uint32_t x, unsigned n) {
    return (x << n) | (x >> (32 - n));   // UB при n = 0!
}
```

- При `n = 0` сдвиг на 32 бита для `uint32_t` — **неопределённое поведение** (UB).
- Компилятор может оптимизировать код непредсказуемым образом.
- Возможны разные результаты на разных платформах.

**Constant-time решение (вариант 4):**

```cpp
uint32_t rotl32(uint32_t x, unsigned n) noexcept {
    const uint64_t xu = static_cast<uint64_t>(x);
    const uint64_t r  = (xu << n) | (xu >> ((32u - n) & 31u));
    return static_cast<uint32_t>(r);
}
```

**Свойства:**

| Свойство | Обоснование |
|---|---|
| Нет UB при n = 0 | Сдвиг на 32 в 64-битном типе определён и равен 0 |
| Нет ветвлений `if/else` | Нормализация через `& 31` |
| Фиксированное число такт | 2 сдвига + `AND` + `OR` |
| Нет обращений к памяти | Только регистры |
| Одинаковое время для любого n и x | Нет data-dependent branching |

### 4.2. Constant-time в GF(2⁸)

**xtime без ветвлений:**

```cpp
uint8_t xtime(uint8_t b) const noexcept {
    const uint8_t hi   = b >> 7;                              // 0 или 1
    const uint8_t mask = static_cast<uint8_t>(0u - hi);       // 0x00 или 0xFF
    const uint8_t red  = static_cast<uint8_t>(p_x_ & 0xFF);   // 0x2B
    return static_cast<uint8_t>((b << 1) ^ (mask & red));
}
```

**Умножение через маскирование младшего бита:**

```cpp
for (int i = 0; i < 8; ++i) {
    const uint8_t bit = bb & 1u;
    const uint8_t mask = static_cast<uint8_t>(0u - bit);
    result ^= (aa & mask);
    aa = xtime(aa);
    bb >>= 1;
}
```

### 4.3. Constant-time в GF(2¹²⁸)

Умножение через маскирование по биту X и младшему биту V:

```cpp
for (int i = 0; i < 128; ++i) {
    const uint8_t bit = (x[i>>3] >> (7 - (i & 7))) & 1u;
    const uint8_t mask = static_cast<uint8_t>(0u - bit);
    for (j = 0; j < 16; ++j) Z[j] ^= V[j] & mask;
    const uint8_t lsb = V[15] & 1u;
    const uint8_t rmask = static_cast<uint8_t>(0u - lsb);
    // V >>= 1
    for (j = 0; j < 16; ++j) { /* ... */ }
    for (j = 0; j < 16; ++j) V[j] ^= R[j] & rmask;
}
```

### 4.4. Constant-time сравнение тегов

**Опасная реализация (early exit):**

```cpp
if (std::memcmp(tag1, tag2, 16) == 0) return true;   // ← утечка!
```

`memcmp` выходит из цикла при первом несовпадении → по времени можно определить позицию первого расхождения.

**Constant-time решение:**

```cpp
bool GCM::ct_compare(const Tag& a, const Tag& b) noexcept {
    uint8_t acc = 0;
    for (size_t i = 0; i < 16; ++i) {
        acc = static_cast<uint8_t>(acc | (a[i] ^ b[i]));
    }
    return acc == 0;
}
```

Все 16 байт обрабатываются **безусловно**. Время не зависит от количества совпадающих байт.

### 4.5. Отсутствие LUT в hot path

| Компонент | LUT? | Что используется вместо |
|---|---|---|
| S-box GF(2⁸) | ⚠️ Строится один раз при инициализации | Вычисление `Affine(a²⁵⁴)` для построения |
| H-блок Belt | ⚠️ Строится один раз | Вычисление из GF(2⁸) |
| GF(2¹²⁸) multiply | ❌ Нет | 128 итераций с маскированием |
| ROTL/ROTR | ❌ Нет | Побитовые операции |

**Примечание:** таблицы S-box и H-бокс хранятся как `std::array<uint8_t, 256>` фиксированного размера. Обращения к ним в hot path (`h()` в Belt) формально дают LUT-зависимость от данных. Для полной Constant-time защиты (задача варианта 12) следовало бы заменить `h_box_[b]` на вычисление `Affine(inverse(b))` на лету. **Задача варианта 4** этого не требует.

```cpp
uint8_t GF256::xtime(uint8_t b) const noexcept {
    const uint8_t hi   = static_cast<uint8_t>(b >> 7);
    const uint8_t mask = static_cast<uint8_t>(0u - static_cast<unsigned>(hi));
    const uint8_t red  = static_cast<uint8_t>(p_x_ & 0xFF);
    const uint8_t shifted = static_cast<uint8_t>(b << 1);
    return static_cast<uint8_t>(shifted ^ (mask & red));
}
```

uint8_t GF256::inverse(uint8_t a) const noexcept {
    const uint8_t a2   = multiply(a, a);
    const uint8_t a4   = multiply(a2, a2);
    const uint8_t a8   = multiply(a4, a4);
    const uint8_t a16  = multiply(a8, a8);
    const uint8_t a32  = multiply(a16, a16);
    const uint8_t a64  = multiply(a32, a32);
    const uint8_t a128 = multiply(a64, a64);
    uint8_t res = a2;
    res = multiply(res, a4);
    res = multiply(res, a8);
    res = multiply(res, a16);
    res = multiply(res, a32);
    res = multiply(res, a64);
    res = multiply(res, a128);
    return res;
}

**Приложение Б.3.** `rotl32` / `rotr32` (Constant-time ROTL/ROTR, задача варианта 4)

```cpp
inline uint32_t rotl32(uint32_t x, unsigned n) noexcept {
    const uint64_t xu = static_cast<uint64_t>(x);
    const uint64_t r  = (xu << n) | (xu >> ((32u - n) & 31u));
    return static_cast<uint32_t>(r);
}

inline uint32_t rotr32(uint32_t x, unsigned n) noexcept {
    const uint64_t xu = static_cast<uint64_t>(x);
    const unsigned m = (32u - n) & 31u;
    const uint64_t r = (xu << m) | (xu >> ((32u - m) & 31u));
    return static_cast<uint32_t>(r);
}
```

bool GCM::ct_compare(const Tag& a, const Tag& b) noexcept {
    uint8_t acc = 0;
    for (size_t i = 0; i < kTagBytes; ++i) {
        acc = static_cast<uint8_t>(acc | (a[i] ^ b[i]));
    }
    return acc == 0;
